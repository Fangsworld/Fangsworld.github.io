# 博客分类/标签系统拓展 - 需求计划文档

## 📋 项目概述

### 项目名称
博客分类/标签系统动态化管理

### 项目背景
当前博客的分类和标签系统存在以下限制：
- 分类硬编码在代码中，无法动态管理
- 标签仅存储在文章 frontmatter 中，无关联关系
- 缺少统计和筛选功能
- 无管理后台，需要修改代码来调整分类/标签

### 项目目标
构建一个灵活、可扩展的分类和标签管理系统，实现：
1. 动态化分类和标签管理
2. 多维度内容筛选
3. 可视化管理界面
4. 数据驱动的运营决策

### 项目价值
- **内容组织**：更好的内容分类和发现
- **用户体验**：便捷的内容浏览和筛选
- **运营效率**：可视化管理，无需改代码
- **数据洞察**：了解用户偏好，优化内容策略

### 表结构定义

#### categories 表

```sql
CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    slug TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    description TEXT,
    parent_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    icon TEXT,
    color TEXT,
    sort_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    meta_title TEXT,
    meta_description TEXT,
    meta_keywords TEXT,
    article_count INTEGER DEFAULT 0,
    total_views INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX categories_slug_idx ON categories(slug);
CREATE INDEX categories_parent_id_idx ON categories(parent_id);
CREATE INDEX categories_sort_order_idx ON categories(sort_order);
CREATE INDEX categories_is_active_idx ON categories(is_active);
```

#### tags 表

```sql
CREATE TABLE tags (
    id SERIAL PRIMARY KEY,
    slug TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    description TEXT,
    color TEXT,
    sort_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    aliases TEXT[],
    article_count INTEGER DEFAULT 0,
    total_views INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX tags_slug_idx ON tags(slug);
CREATE INDEX tags_sort_order_idx ON tags(sort_order);
CREATE INDEX tags_is_active_idx ON tags(is_active);
```

#### article_categories 表

```sql
CREATE TABLE article_categories (
    id SERIAL PRIMARY KEY,
    article_id INTEGER NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
    category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    is_primary BOOLEAN DEFAULT false,
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(article_id, category_id)
);

CREATE INDEX article_categories_article_idx ON article_categories(article_id);
CREATE INDEX article_categories_category_idx ON article_categories(category_id);
```

#### article_tags 表

```sql
CREATE TABLE article_tags (
    id SERIAL PRIMARY KEY,
    article_id INTEGER NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
    tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(article_id, tag_id)
);

CREATE INDEX article_tags_article_idx ON article_tags(article_id);
CREATE INDEX article_tags_tag_idx ON article_tags(tag_id);
```

## 🔧 技术方案

### 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 数据库 | PostgreSQL + Neon | 云数据库 |
| ORM | Drizzle ORM | 类型安全的查询 |
| 后端 | Next.js App Router | API 路由 |
| 前端 | React + TypeScript | 组件开发 |
| 样式 | Tailwind CSS | 样式开发 |
| 图标 | lucide-react | 图标库 |
| 表单 | react-hook-form + zod | 表单验证 |

### 关键技术决策

#### 1. 分类层级实现

**方案选择：**
- ✅ 使用 `parent_id` 自关联（简单、高效）
- ❌ 使用嵌套集模型（复杂、过度设计）

**理由：**
- 分类层级一般不超过 3 层
- 查询频率高，需要性能好
- 维护简单

#### 2. 标签搜索

**方案选择：**
- ✅ PostgreSQL ILIKE（模糊搜索）
- ❌ 全文搜索引擎（初期不需要）

**理由：**
- 标签数量不会特别多（< 1000）
- ILIKE 性能足够
- 降低复杂度

#### 3. 缓存策略

**缓存内容：**
- 分类树（5 分钟）
- 热门标签（10 分钟）
- 标签统计（1 小时）

**缓存方式：**
- React Cache（服务端）
- Next.js ISR（页面级）
