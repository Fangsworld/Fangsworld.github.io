# 商业化验证计划

记录日期：2026-11-24
状态：讨论初稿，待本人修改；尚未开始招募、报价或收费。

## 目标与假设

先完成少量「真实客户付费、获得价值、愿意继续使用」的闭环，再决定投入哪款产品。现有作品和文章证明了产品实践，但目前未核对真实收入、活跃、留存与获客成本；优先级是待验证判断。

主线假设：产品服务带来现金和客户理解，言界积累可复用能力，文章与作品建立信任。

## 候选业务

| 优先级 | 方向 | 潜在客户 | 待验证的交付 |
| --- | --- | --- | --- |
| 1 | AI 产品诊断与小范围落地 | 已有业务和原型的小团队 | 找出一个关键使用问题，交付诊断、改进方案与可验证的关键流程 |
| 2 | 言界写作工作流服务 | 持续表达的专业人士、创始人、小型内容团队 | 本人确认的风格准则、素材与引用流程、真实文章示例和使用指导 |
| 3 | 核心 App 付费 | 有重复需求的个人用户 | 先比较言界与迷宫英语的真实使用，集中选择一款验证 |

一念暂作为可复用能力观察；输入法继续关注稳定性与独特价值。课程、会员、广告待案例和受众需求明确后再考虑。所有方向均不代表收入预测。

## 启动后的 30 天

### 第 1 周：明确客户和问题

- [ ] 本人确认目标收入、每周可用时间、可接受预算和最迟验证日期。
- [ ] 选择一个客户群与一个具体任务，不同时推广全部项目。
- [ ] 访谈 10 名潜在客户，记录当前流程、频率、损失、现有替代方案及实际支出。
- [ ] 盘点各 App 的真实活跃、留存、付费和支持成本；没有数据则先列缺口。

### 第 2 周：提出可购买的试点

- [ ] 选择一个反复出现的问题，制作一页服务说明。
- [ ] 写清交付物、周期、客户所需材料、验收标准、修改次数和维护边界。
- [ ] 本人确定试点报价与成本底线，再向目标客户提出付费方案。
- [ ] 寻找首批 2—3 个付费试点；数量是试验目标，不是已确认订单。

### 第 3 周：交付与观察

- [ ] 按约定完成交付，记录工时、模型及部署成本、修改次数和支持负担。
- [ ] 观察客户是否独立使用，比较任务完成时间、质量与返工情况。
- [ ] 经客户授权后整理案例，保留事实与限制，公开前确认可披露内容。

### 第 4 周：决定继续、调整或停止

- [ ] 收集继续使用、再次付费或转介绍的实际行为。
- [ ] 核算单次交付收入减直接成本及工时后的结果。
- [ ] 区分客户特例与重复需求，决定继续服务、产品化或更换问题。
- [ ] 选定下一阶段唯一商业主线，明确其余项目维护投入。
